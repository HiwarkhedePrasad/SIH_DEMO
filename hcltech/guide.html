How to approach coding questions

The 8-step framework (use on EVERY problem)

Step 1 — Understand input & output

Rewrite the problem in one line: "Given X, produce Y." Identify exact input format (N then array? lines?) and output format (YES/NO? index? 2 decimals?). 50% of fresher failures are format errors, not logic errors.

Step 2 — Create small examples

Run 2 tiny cases by hand, including one trivial (N=1, empty) and one with duplicates. Example: second-largest [9,9,7] → answer 7, not 9.

Step 3 — List edge cases FIRST

N=0, N=1, all-negative, all-same, already-sorted, K>N, key absent. Write them as comments before coding.

Step 4 — Simplest solution first

Brute force that works beats clever code that doesn't. Nested loops / extra array is FINE for Easy problems — submit it, then optimise only if time remains.

Step 5 — Complexity check

Ask: N ≤ 10³? O(N²) passes. N ≤ 10⁵? Need O(N log N) or O(N). Say it in your head before coding.

Step 6 — Look for THE pattern

Sorted + search → binary search. Pairs summing to T → hash map. Order-preserving filter → two pointers. Counting → frequency dict. Balanced symbols → stack. Extremes → best-so-far.

Step 7 — Write clean code

Meaningful names, int(input()), solve in functions. No one-line golf — assessors and interviewers must read it.

Step 8 — Manual test

Dry-run with your Step-2 example + one edge case. Check off-by-one (range bounds), empty input, and output format. Only then submit.

Anti-stuck protocol (if blank for 5 min)

1) Solve N=3 by hand and stare at your steps — that IS the algorithm. 2) Drop one constraint (assume sorted / assume distinct) and solve that. 3) Write brute force and submit — partial score > zero. 4) Never switch language mid-test.
